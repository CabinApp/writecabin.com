Giving Cabin Its Shape

Well, I've done a lot of STUFF

3 min read

It's been a long time since my last blog post. And I left with having this massive feature list and a foggy idea of how to implement it. Well, I've done a lot of STUFF since then, and this is an update on all of that.

Storing Brainwaves

At the end of my last blog, I mentioned that I still had to come up with a way to store data. I had defined all the features, but still no way to store it (considering Cabin is a local-first app). So after a lot of thinking, I settled on a few different file formats such as .cabinpage, .cabinconfig, and .cabinnote. Innovatively named, these formats are mashups of existing formats such as Markdown, XML, and TOML.

After that, I built some simple project folder structures to see how a Cabin project would look like on your computer and created samples of the final file formats.

User Experience

The next problem I tackled was user experience. In one of my previous blogs, I introduced a beautiful term called progressive complexity. So I sat and actually translated the flowery English into actual stuff you can do on Cabin. The main concept was that you can add a component to the workspace when you feel like it.

I explored different ways of adding components, such as a component library, a keyboard shortcut that opens a massive search, an always-visible component library, etc. I'm still undecided, but I have an idea in my head about how a person would use it.

I also took inspiration from, possibly my favourite app, Obsidian and thought about making each component a panel, and you can resize, rearrange, and dock these panels.

UI Design

I then moved onto UI design. Let it be known to the world, I am not a person with skills in making things look good. But I have a rough idea for software at least.

I experimented on Penpot, but later moved to prototyping with actual code using ChatGPT because it was easier to see my changes. Also, the Penpot designs looked like this:

And I do not mean Penpot is bad, it's a wonderful tool, but it's just not meant for me.

After playing around with code prototyping, I realised flat design wasn't really working. So I made a bold choice and moved to neumorphism. If you know a bit about web design and are familiar with a few trends, you may realise that this is a bit of a risky move.

Conventionally, neumorphism has been criticised for its lack of accessibility, which I agree with. The soft shadows make it hard to distinguish elements for those with impaired vision. I tried to make my designs as accessible as possible, and will do a final web accessibility check (such as WCAG) before the final version of Cabin.

Regardless, it was a major improvement:

Bouncy Buttons

Another issue I found with neumorphism was that it was hard to distinguish between pressing a button and an already-pressed button. Therefore, I opted for BOUNCY BUTTONS. You can view a sample here. This also adds the feeling of a tactile interface, so it feels like you are actually interacting and touching the interface.

Alright, so that's all I've done in the past few months. I now need to probably focus on using this new UI system to create actual mocks for the workspaces (just tiny web models) to see how the final interface would look.

And then I have to build the actual thing, so that's there as well.
